## 二、根因定位过程

### 1. 源码vs构建产物对比
```
源码 (ReportPage.tsx line 1703): async (evt) => { ... evt?.target ... }
构建产物 (dist/assets/ReportPage): () => alert(...)  // 完全不同！
```
**发现**: 源码修改了，但构建产物没有反映修改。

### 2. strace追踪文件读取
```bash
strace -e openat npx vite build 2>&1 | grep ReportPage
```
**发现**: esbuild读取的是 `/home/admin/hermes-agent/web/G005/assets/ReportPage-A7fkv-VE.js`
而非 `src/pages/ReportPage.tsx`

### 3. assets/目录时间戳
```bash
ls -la assets/ReportPage-A7fkv-VE.js
# -rw-r--r-- 1 admin admin 57426 May  4 07:39  # 早于bug修复时间
```
**发现**: `assets/`目录（包含预编译文件）日期为May 4 07:39，早于bug修复时间09:44。

### 4. index.html分析
```html
<script type="module" crossorigin src="/assets/index-CI6ErSQA.js"></script>
```
**发现**: index.html硬编码指向旧预编译文件，Vite构建时遇到这个引用，直接使用过期预编译代码，跳过了所有`src/pages/`的编译。

### 5. Git历史追溯
`commit 70aff87`（G005 v0.15.0六大核心升级）把预编译的`assets/`目录提交进了git，同时修改index.html为直接引用预编译文件。

### 根因总结
```
commit 70aff87把预编译assets/目录提交进git
     ↓
index.html改为src="/assets/index-CI6ErSQA.js"直接引用预编译文件
     ↓
Vite构建时遇到硬编码引用，跳过src/pages/编译
     ↓
使用过期的预编译代码（v0.9.0时代）
     ↓
无论怎么修改源码都无效
```

## 六、经验总结

### 教训
1. **预编译目录不应进git**: `assets/`目录（node_modules之外的预编译产物）不应提交，应在`.gitignore`中排除
2. **index.html禁止硬编码**: Vite构建的hash是自动生成的，不应在index.html中硬编码

### 检查清单（未来构建前必查）
- [ ] index.html不应有`<script src="/assets/...">`硬编码
- [ ] assets/目录不应在git中（检查.gitattributes/.gitignore）
- [ ] 构建后检查dist中chunk大小是否变化
- [ ] 每次构建后grep验证关键代码确实在dist中
