# G005 v3.0.0 — 阶段推送工作流

> **目的**:每完成一个开发阶段立即推送到 GitCode `G005-RISv-3.0.0` 仓库
> **仓库**:`git@gitcode.com:liuzhu2026/G005-RISv-3.0.0.git`
> **规则**:每个 Task 完成 → 立即 commit + push(不积压)

---

## 一、推送策略

### 1.1 分支模型

```
main              ← 主分支(稳定,每个阶段合并)
release/v3.0.0   ← v3.0.0 发布分支(初始)
develop           ← 开发分支(日常推送)
feature/*         ← 单个 Task 功能分支(可选)
```

### 1.2 默认推送流程

```
完成 Task #N
   ↓
git checkout develop
git pull origin develop
   ↓
git add -A
git commit -m "feat(W3-W4): <任务名>"
   ↓
git push origin develop
   ↓
在 GitCode 创建 PR: develop → release/v3.0.0
   ↓
用户 review & merge
   ↓
PR merge 后:
   git checkout release/v3.0.0
   git pull origin release/v3.0.0
   (远端 main 反映此阶段)
```

### 1.3 简化模式(快推)

```
完成 Task #N
   ↓
git add -A
git commit -m "feat(W3-W4): <任务名>"
   ↓
git push origin release/v3.0.0    # 直接推到 release 分支
```

用户指定"该仓库是 3.0 专属开发仓库",**默认采用简化模式**。

## 三、Commit 命名规范

### 3.1 Conventional Commits

```
<type>(<scope>): <subject>
```

**Type**:
- `feat` - 新功能
- `fix` - 修复
- `docs` - 文档
- `refactor` - 重构
- `test` - 测试
- `chore` - 杂项
- `perf` - 性能
- `style` - 代码风格

**Scope**:阶段 / 子模块
- `W1` / `W2` / `W3` / ... - 阶段
- `machines` - 状态机
- `i18n` - 国际化
- `security` - 安全
- `a11y` - 无障碍
- `design` - 设计系统
- `test` - 测试
- `ci` - CI/CD
- `obs` - 可观测性

### 3.2 提交样例

```bash
feat(W2): Provider 整合 - antd + I18n + ErrorBoundary + a11y
feat(W2): V3 完整示范页 ReportListV3Page
test(StatusBadge): 14 态徽章组件测试 6 用例
test(a11y): SkipLink + LiveRegion + useScreenReaderAnnouncer
test(useBreakpoint): 7 个响应式 hooks 15+ 用例
test(utils): currency 升级 + 30+ 测试 (Decimal)
test(utils): date 升级 + 30+ 测试 (date-fns)
docs(W1): 推送 GitCode 工作日志
docs(workflow): 阶段推送工作流规范
```

## 四、推送脚本

### 4.1 简化推送(推荐)

```bash
#!/bin/bash
# scripts/push-stage.sh
# 用法: bash scripts/push-stage.sh "feat(W3): 测试覆盖到 50%"

set -e
MESSAGE="${1:-chore: stage update}"

cd "$(dirname "$0")/.."

# 检查状态
if [ -z "$(git status --porcelain)" ]; then
  echo "No changes to commit"
  exit 0
fi

# 提交
git add -A
git commit -m "$MESSAGE"

# 推送(SSH)
git push origin release/v3.0.0

echo "✅ Pushed to gitcode: $MESSAGE"
```

### 4.2 完整流程(含 PR)

```bash
#!/bin/bash
# scripts/push-feature.sh
# 用法: bash scripts/push-feature.sh "feat(W3): 测试覆盖"

set -e
MESSAGE="${1:-chore: update}"

cd "$(dirname "$0")/.."

# 1. 确保在 develop 分支
git checkout develop
git pull origin develop

# 2. 提交
git add -A
git commit -m "$MESSAGE" || echo "Nothing to commit"

# 3. 推送 develop
git push origin develop

# 4. 提示用户创建 PR
echo "📝 请到 GitCode 创建 PR: develop → release/v3.0.0"
echo "   https://gitcode.com/liuzhu2026/G005-RISv-3.0.0/merge_requests/new?source_branch=develop"
```

## 六、推送检查清单

每次推送前:
- [ ] 代码通过 `pnpm typecheck`
- [ ] 代码通过 `pnpm test:run`
- [ ] 代码通过 `pnpm lint`
- [ ] 文档已更新(CHANGELOG / 工作日志)
- [ ] Commit 信息符合 Conventional Commits
- [ ] 工作日志已写

推送后:
- [ ] 在 GitCode 验证 commit
- [ ] 创建 PR(如用 develop 流程)
- [ ] 更新本任务表

## 七、紧急修复流程

如果生产环境出现紧急 bug:

```bash
git checkout main
git pull origin main
# 创建 hotfix 分支
git checkout -b hotfix/critical-issue
# 修复
git add -A
git commit -m "fix: 紧急修复 <描述>"
# 推送到 main + release/v3.0.0
git push origin main
git push origin release/v3.0.0
```
