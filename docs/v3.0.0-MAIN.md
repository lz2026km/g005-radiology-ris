## 🎯 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| **后端策略** | **纯前端优化版** | 用户指定 / 快速变现 |
| **产品定位** | **三甲医院全功能 RIS/PACS** | 高客单价 / 强需求 |
| **部署形态** | **私有化为主 + SaaS 备选** | 医疗数据合规要求 |
| **设计系统** | Ant Design 5 + 自研 Design Tokens | 复用 antd 加速 |
| **移动端** | H5 + 微信小程序(Taro 3) | 复用 React 组件 |
| **国际化** | i18next 替换自研 | 真国际化 |
| **测试** | Vitest + Playwright 双栈 | 单元 + E2E |
| **AI 增强** | DeepSeek 8 类 → 16 类 | 差异化 |
| **状态机** | XState 5 完整落地 | 14 态已有数据 |
| **文档化** | Storybook 8.4 全面启用 | 组件级 |

## ⚠️ 风险与缓解

| 风险 | 等级 | 缓解策略 |
|------|------|----------|
| 纯前端无法对接真实 PACS | 高 | 强调"前端产品 + MSW 模拟",销售时透明;提供"对接真实 PACS 集成服务"增值包 |
| 三甲医院销售周期长 | 高 | 先切入二级 + 医联体 + 民营医院,后转三甲 |
| 数据合规落地成本高 | 高 | 等保三级规划,先做基础,渐进合规;不承诺等保四级 |
| 45 个 `@ts-nocheck` 清理工作量大 | 中 | 分批清理,W7-8 集中清理 |
| 移动端 PWA / 小程序选型 | 中 | Taro 3 复用 React 组件,1 周内可出 MVP |
| 十大厂商情报不完整 | 中 | 公开资料 + 行业报告 + 招股书 + 客户调研 |
| 商业化测试 60% 工作量大 | 中 | 优先级排序,核心业务先(报告/危急值/CA 签名) |
| 设计师 / 移动端资源不足 | 中 | 用 Ant Design Pro + ProComponents 减少设计成本 |
