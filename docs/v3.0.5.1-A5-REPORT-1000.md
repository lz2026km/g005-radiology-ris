### 0.2 与现有 17 态状态机的关系

每条升级点都映射到 src/machines/reportMachine.ts 中的 23 种事件,并保留 4 个守卫(rejectReasonRequired / qualityScoreSufficient / rectifyAttemptsBelowMax / supplementAttemptsBelowMax)。状态机已是 v3.0.2.10 17 态,本规范不修改状态机,只补充事件 handler / 守卫用例 / UI 触发。

### 0.3 命名规范

- **ID**:R3.{MODULE}.{NNN},NNN 从 001 起按顺序连续编号(每个子模块内独立)
- **Name**:中文名 / English Name
- **Type**:UI control / API endpoint / state machine event / MSW mock / type / e2e test / story / i18n key
- **Priority**:P0(必做,阻塞 GA)/ P1(应做,GA-1)/ P2(可延后,GA-2)
- **Module**:REVIEW / QUALITY / WRITING / SIGN / AMEND / AI / DIST / INTEGRATION / OTHER
- **State machine event**:事件名或 - 表示非事件型
- **MSW handler**:METHOD /api/v1/path 或 -
- **Acceptance**:可验证的验收条目
- **Dependencies**:前置 ID
- **Estimated hours**:0.5-4 小时

针对 5 大关键用户旅程:

1. **审核旅程**:书写 -> 提交 -> 初审 -> 终审 -> CoSign -> 签发 -> 发布
2. **驳回旅程**:审核 -> 驳回(必填 reason) -> 整改 -> 重新提交 -> 通过
3. **修订旅程**:已发布 -> 启动修订(必填 reason) -> 审批 -> 编辑 -> 完成 -> 重新发布
4. **补充旅程**:已发布 -> 启动补充(守卫 <3) -> 完成 -> 重新发布
5. **AI 旅程**:选择报告 -> 一键 AI 初稿(mock) -> 编辑 -> 提交审核
