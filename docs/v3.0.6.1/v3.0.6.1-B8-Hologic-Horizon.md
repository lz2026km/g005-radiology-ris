## §1 Hologic Horizon 概述与文档定位

### 1.1 厂商背景

**Hologic, Inc.**(NASDAQ: HOLX)成立于 1985 年,总部位于美国马萨诸塞州 Marlborough。Hologic 的业务重心高度集中于**女性健康**,在全球乳腺影像领域处于**绝对领先地位**:根据 2024 年 Hologic 年报披露,公司全球乳腺 X 线摄影(Mammography)装机量超过 **30000 台**,在美国 FFDM 市场占有率约 **55-60%**,在数字乳腺断层摄影(Digital Breast Tomosynthesis, DBT)市场占有率约 **70%**(估算口径,含 3D 升级套件)。

Hologic 在中国大陆的业务通过**豪洛捷医疗(北京)有限公司**和**豪洛捷科贸(上海)有限公司**开展,2024 年公开招标数据显示中国三甲妇幼保健院、肿瘤医院、女性专科医院装机集中度极高。其代表性客户群:

- 北京大学第一医院、北京大学肿瘤医院、中国医学科学院肿瘤医院

- 中山大学孙逸仙纪念医院、中山大学附属第一医院
- 四川省妇幼保健院、湖南省妇幼保健院

### 1.2 为何单列 B8 而非并入 B1~B7

在 v3.0.6.1 周期前,G005 团队曾考虑将 Hologic 乳腺业务并入 B1(GE)或 B3(Philips)的"乳腺模块",但最终决定**单列为 B8 调研文档**,原因:

1. **专科差异显著**:Hologic 乳腺/骨密度业务**完全不与 GE/Philips/Fujifilm 通用 PACS 共享后端架构**,Hologic 的乳腺影像数据流(尤其 DBT 体数据 ~ 1-3 GB/case)需要独立 DICOM 路由、归档策略、缓存机制,无法与胸腹部 CT/MR 通用 PACS 简单合并。
2. **CAD 生态独立**:R2 ImageChecker 是**唯一获得 FDA PMA 和 NMPA 三类**的乳腺 CAD 产品,与通用 PACS 工作站集成模式(挂件 vs. 嵌入式)截然不同。
3. **骨密度自成体系**:Hologic DEXA 的数据流是**非 DICOM 主体**(早期系统使用私有协议,新一代支持 DICOM DX/CR + 自定义 IOD),与放射 PACS 主干解耦。
4. **法规壁垒**:中国 NMPA 对乳腺 CAD、对比增强能谱摄影、DBT 的注册路径与通用放射设备不同,需专项资质。

### 2.4 数据量与归档策略

乳腺影像数据量与放射常规 CT/MR 不同,典型 case 规模:

| 检查类型 | 单 case 体量 | 单次检查序列数 | 备注 |
|---|---|---|---|
| **FFDM (2D)** | ~ 30-60 MB(4 view) | 4-6 | 标准 MLO + CC 体位 |
| **DBT (3D)** | ~ 600 MB - 1.5 GB | 60-80 slices × 2 侧 | 迭代重建 + 多平面 |
| **CESM** | ~ 200-400 MB | 高/低能 × 多体位 | 双能曝光 |
| **FFDM + DBT 联合** | ~ 1.5-3 GB | 4 view × DBT | 当前主流筛查协议 |
| **骨密度 (DEXA)** | ~ 2-10 MB | 1-3 部位 | 单能 X 线 + 扫描矩阵 |
| **穿刺活检标本** | ~ 30-100 MB | 5-20 标本块 × 多角度 | Trident HD |

由此衍生**三个关键归档策略议题**(v3.0.7+ 必须与客户架构师明确):

1. **DBT 在线/近线分层**:1-3 GB/case × 每日 100+ 例的乳腺中心,30 天近线容量需 3-5 PB,**传统 PACS 在线存储成本不可接受**;
2. **R2 ImageChecker GSPS 生命周期**:CAD 标记需与原图绑定,但医师复审后多数标记被"接受/拒绝",长期归档时是否保留原始 GSPS 涉及法规(中国《医疗器械监督管理条例》要求源数据保存 ≥ 30 年);
3. **骨密度数据与放射 PACS 共享 vs. 独立**:Hologic DEXA 早期系统不支持 DICOM,新一代支持但 IOD 不一致,需评估是否纳入主 PACS 或保留独立 Hologic 归档。

## §3 调研要点:三大产品族

### 3.1 Hologic Horizon Medical Imaging (乳腺 X 线 / DBT)

**核心设备**:Selenia Dimensions(经典款,已停产维护但仍装机)、3Dimensions(主力,2024 年中国新装机主流)、3Dimensions Clarity HD(高分辨率探测器版本)。

**关键能力清单**(与 G005 RIS 集成相关):

1. **多模态采集**:单台设备可同时输出 FFDM、DBT、CESM,技师在采集工作站(Hologic Acquire)按"协议包"配置,G005 RIS 需识别协议包以正确触发报告模板。
2. **DBT 重建引擎**:Hologic DBT 重建在采集工作站侧完成,生成 DICOM 3D 体数据(Series Description 包含 `Tomosynthesis` 关键字),G005 RIS 阅片客户端需具备 3D 体绘制能力(原生 Web 方案:Three.js + Cornerstone3D)。
3. **I-View 2.0 CESM**:对比增强能谱乳腺摄影,使用碘造影剂,采集双能(高/低 kV)图像并合成减影,G005 RIS 工作流需触发"增强检查"语义,并记录造影剂名称、剂量、注射时间。
4. **压迫参数完整采集**:Hologic 设备自动记录压迫力(N)、压迫厚度(mm)、压迫板型号、皮肤接触面积,这些数据可通过 DICOM `(0019,xx30-31)` 私有标签 + IHE REM 暴露记录查询,G005 RIS 报告端可填充至乳腺剂量章节(中国《乳腺 X 射线摄影质量控制指南》要求)。
5. **技师质量评分 (Tech QC)**:采集时技师可对每幅图像做"接受/重照"标记,通过 DICOM `(0040,A730)` Content Sequence + 私有 term 实现,G005 RIS 工作列表应回显技师 QC 状态。
6. **筛查召回管理**:Hologic Securview DX 工作站内置"BIRADS 0 = 需要召回"标记,与 IHE Mammography Profile 兼容,G005 RIS 工作流引擎应能订阅 BIRADS 0 触发召回任务。

**G005 RIS 应关注的 Hologic 数据元素**(报告模板需消费):

| 元素 | DICOM 路径 | 报告章节映射 |
|---|---|---|
| 检查类型 (MG/DBT/CESM) | `(0008,0060)` Modality + Protocol | 检查方法学 |
| 体位 (MLO/CC/ML/AT) | `(0018,5101)` View Position + Private | 检查体位 |
| 压迫力 / 厚度 | `(0019,xx30-31)` Hologic Private | 质量控制 |
| 平均腺体剂量 (AGD) | `(0040,0316)` Organ Dose | 剂量记录 |
| BIRADS 分类 | DICOM SR TID 4200 | 报告结论 |
| CAD 标记数 | R2 ImageChecker GSPS count | 报告参考 |

### 3.2 R2 ImageChecker Mammo CAD (计算机辅助检测)

**产品定位**:R2 Technology 于 2006 年被 Hologic 收购,产品线更名为 **Hologic R2 ImageChecker**。当前主力版本为 **ImageChecker 10.x**,支持 2D FFDM 与 3D DBT 双模态。

**技术能力**(基于公开白皮书与 NMPA 注册资料):

- **2D FFDM CAD**:检出敏感度:微钙化簇 ~ 98%、肿块 ~ 89%、结构扭曲 ~ 80%(Hologic 自报,需独立验证),假阳标记率 ~ 0.5-1.5 标记/case。
- **3D DBT CAD**:基于深度学习的卷积网络,标记速度 < 30 秒/case,可同时输出 2D 合成图(MammoPad 2D synthetic)与 3D 体数据标记。
- **集成方式**:
  - **嵌入式**:R2 Server 直接嵌入 Hologic Securview DX 工作站,标记以 DICOM GSPS `(0029,xx50-52)` 返回;
  - **挂件式**:R2 作为独立服务器,接受 DICOM C-STORE 输入,输出 GSPS + DICOM SR 至 PACS;
  - **API 方式**(新):R2 ImageChecker 10.x 提供 REST API `/api/v1/cad/analyze`(需 Hologic 现场 License),返回 JSON 结果,适合 G005 RIS 直接消费。

**与 G005 RIS 的对接要点**(v3.0.7+ 实施时需评估):

1. **挂件式 vs. API 方式**:中国客户普遍已部署挂件式 R2,G005 RIS 推荐采用**监听 GSPS + DICOM SR** 模式,**不**直接调用 R2 REST API,以避免双链路分歧。
2. **CAD 标记在报告中的呈现**:G005 RIS 报告编辑器应允许医师**逐标记确认/拒绝**(支持 GSPS "Mark Source Applicability" 机制),并将医师终审结论反向写回 DICOM SR。
3. **CAD 假阳过滤**:Hologic R2 在中国致密腺体人群中假阳率偏高(独立研究 ~ 2-4 标记/case),G005 RIS 应提供"批量标记筛选"工作流,允许医师一键隐藏低置信度(< 0.3)标记。
4. **Genius AI Detection 与 R2 协同**:Hologic 2023 年推出 Genius AI Detection(基于深度学习的 DBT 阅片辅助),与 R2 ImageChecker 并行运行,**两者结果不冲突**:Genius AI 给出 case 级别风险评分,R2 给出 lesion 级别标记。G005 RIS 报告应分别展示。

### 3.3 Hologic Bone Densitometry DEXA (骨密度)

**核心设备**:Hologic Horizon 系列(QDR 系列后继型号),主力机型 Horizon Wi(WiFi 移动)、Horizon Ci(临床固定)、Horizon A(全身 + Body Composition)。

**关键特性**(与放射 PACS 差异显著):

1. **测量部位**:腰椎正位(L1-L4)、髋关节(Femoral Neck/Total Hip)、前臂(Radius 33%/Total)、全身(Whole Body);
2. **输出指标**:BMD(Bone Mineral Density, g/cm²)、T-Score、Z-Score、FRAX 10 年骨折风险、Body Composition(瘦体重/脂肪组织);
3. **数据 IOD**:新一代支持 DICOM DX/CR IOD + 私有 Hologic IOD(`(0019,xx40)` 系列),早期系统使用 ASCII 文本 `.rpt` 文件 + 私有二进制 `.qdr`;
4. **报告形态**:Hologic DEXA 内置打印机打印纸质报告 + 数字 PDF,**不**生成 DICOM SR(虽然技术上可行,但 Hologic 默认工作流不出 SR)。
5. **法规属性**:DEXA 在中国属于**放射诊疗目录**管理,需《辐射安全许可证》、技师证、医师证,且剂量记录纳入年度评估。

**G005 RIS 集成 DEXA 的难点**:

- **数据 IOD 不统一**:中国大量装机是 2015 年前的 QDR 系列,只产 `.qdr` + `.rpt`,需 Hologic 现场升级或定制 DICOM 转换中间件;
- **报告工作流分离**:DEXA 报告通常由**临床医生**(内分泌科、骨松科、妇科)而非放射科医师签发,与 G005 RIS 默认放射科签发模型不匹配;
- **无 DICOM SR**:G005 RIS 报告引擎消费 DICOM SR 的逻辑在 DEXA 场景失效,需扩展支持"非 SR 报告数据"(BMD、T/Z Score 直接映射);
- **骨松随访管理**:DEXA 强调**纵向对比**(同一患者不同年度的 BMD 趋势曲线),Hologic APEX 软件内置随访功能,G005 RIS 需评估是否复用其随访引擎还是自建。

**结论**:DEXA 集成在 v3.0.7+ 优先级**低于**乳腺 MG/DBT/CAD 业务,建议在 v3.0.8+ 或客户专项需求时启动。

| **穿刺活检** | **是** (Brevera) | 否 | 中 | 否 | 否 |

**关键发现**:Hologic 在**乳腺专科深度**和**骨密度/活检产品矩阵完整度**上是国际厂商中唯一具备全产品线的厂商,GE/Siemens/Philips/Fujifilm 均不具备可对照的骨密度产品。这是 G005 RIS 把 Hologic 单独列为 B8 而非并入 B1~B3 的根本原因。

### 4.2 中国市场对标

国内乳腺影像厂商:**联影**(uMI 乳腺 PET-MR)、**东软**(NeuCare Mammo)、**赛诺威盛**(Senographe)等均处于起步阶段,**临床装机量与 Hologic 差距至少 10 年**。在妇幼专科医院、肿瘤医院乳腺中心,**Hologic 装机占比超过 60%**(2024 年公开招标数据估算)。

这意味着 G005 RIS 的中国客户群中,**只要涉及乳腺影像,大概率会遇到 Hologic**。即使 v3.0.6.1 不集成 Hologic,售前与实施团队也必须具备 Hologic 数据流知识。

### 4.3 G005 RIS 与 Hologic 中国合作现状

**截至 2026 年 6 月,G005 与 Hologic 中国(豪洛捷医疗)未建立正式商务/技术合作**。文档作者建议的接触路径:

1. 通过中国 PACS 集成商联盟(CHIMA、CHINC)渠道建立首次接触;
2. 邀请 Hologic 亚太技术团队参加 v3.0.7 启动会,明确"白盒集成"边界(G005 需要访问的 DICOM 私有元素列表);
3. 与 Hologic 签订 NDA 后获取 R2 ImageChecker 10.x REST API 文档与 Genius AI Detection 接口规范;
4. 评估 Hologic "PowerConnect" 合作伙伴计划(全球性,亚太区可能未覆盖)。

### 5.2 关键模块设计要点

**(1) DBT 3D 体绘制前端**:复用 G005 RIS v3.0.6.1 已有的 Cornerstone3D 基础设施(B1/B2/B3 中已交付),无需新增 3D 引擎依赖。差异点是 DBT 数据集特别大(1-3 GB/case),**必须**采用渐进加载 + LOD(Level of Detail)策略,建议三阶段:

- 阶段 1:加载 MLO/CC 2D 合成图(~ 50 MB),< 1 秒呈现;
- 阶段 2:加载 DBT 粗采样体数据(降采样 4x,~ 200-400 MB),~ 5 秒呈现;
- 阶段 3:流式加载完整 DBT(~ 1-3 GB),后台完成,医师无需等待。

**(2) R2 CAD 标记交互组件**:基于 DICOM GSPS 标准,允许医师在 Web 端逐标记"接受/拒绝",并将状态反向写回 DICOM PS 3.4 Annex C.11.16 "Presentation State Append" 机制。组件需支持:

- 标记符号切换(微钙化 = 圆点、肿块 = 圆圈、结构扭曲 = 星形);
- 标记置信度可视化(Genius AI Detection 分数以热力色阶叠加);
- 批量筛选(隐藏置信度 < 阈值的标记);
- 与报告 BIRADS 章节联动(标记被拒绝时自动提示修订).

**(3) DEXA 报告消费器**:DEXA 不产 DICOM SR,G005 RIS 报告引擎需扩展"非 SR 数据模型",支持以下输入字段:

```
interface DexaReportInput {
  patientId: string;
  examDate: string;          // ISO 8601
  scannerModel: string;      // "Horizon Wi"
  measuredSites: Array<{
    site: 'L1-L4' | 'FemoralNeck' | 'TotalHip' | 'Radius33' | 'WholeBody';
    bmd: number;              // g/cm²
    tScore: number;           // 标准差
    zScore: number;           // 标准差
    whoCategory: 'Normal' | 'Osteopenia' | 'Osteoporosis' | 'SevereOsteoporosis';
  }>;
  fraxScore?: {              // FRAX 10 年骨折风险
    majorOsteoporotic: number;  // %
    hip: number;                // %
  };
  followUpRecommendation?: string;
}
```

**(4) Hologic 私有标签解码器**:作为 G005 RIS BFF 的独立 npm 包 `@g005/dicom-hologic-decoder`,输入 DCMTK 解析后的 dataset 对象,输出标准化 TS 接口。覆盖 §2.3 列出的全部私有元素 + 持续维护新发现的私有标签。
