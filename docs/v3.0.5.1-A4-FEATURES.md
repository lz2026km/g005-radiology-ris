# v3.0.5.1-A4 前端功能深度审计报告

> **审计范围**：`src/pages/**/*.tsx` 共 **122 个页面**（`src/routes/routeTable.tsx` 注册的 122 个 lazy 路由 + Login + Forbidden）
> **审计目标**：识别功能深度不足、可投产度低于 7/10 的页面，输出 Bottom 50 清单与补强建议
> **审计口径**：功能性复杂度（CRUD / 状态机 / 表单） + 单屏可交互度（无纯只读） + 数据真实度（mock vs 真实 API） + 多模态适配 + 工程化（@ts-nocheck / TODO / 拆分度）
> **方法学**：源码静态扫描 + 路由表交叉验证 + 业务复杂度赋值打分
> **数据快照时间**：2026-06-17

---

## 0. Executive Summary

| 指标 | 数值 | 占比 |
|------|------|------|
| 总页面数 | 122 | 100% |
| 9–10 分（生产级） | 7 | 5.7% |
| 7–8 分（功能丰富） | 38 | 31.1% |
| 4–6 分（基础列表/表单） | 56 | 45.9% |
| 0–3 分（占位/mock-only） | 21 | 17.2% |
| 7 个"超 2000 行待拆分"页面 | 7 | 5.7% |
| 使用 `// @ts-nocheck` 页面 | 约 60 | 49% |
| 完全没有后端 API 集成 | 约 90 | 74% |

**核心结论**：

1. 系统已完成"广度铺设"（122 页覆盖放射科全场景），但**深度严重不足**：近 18% 的页面是占位级实现，近 46% 仅为基础列表。
2. **Bottom 50** 中有 18 个页面是单屏只读 mock（部门 / 财务 / 监管 / 多端 子系统），缺少"增删改"入口，无法承接生产业务。
3. 7 个超大文件（>2000 行）已用 `// TODO v3.0.4: 拆分` 标记，**v3.0.5.1 仍未落地**，建议作为本版本 P0 任务。
4. AI、知识库、报告 KPI 三个 R7 主题群（v1.0.7）功能深度最高，**可作为 9–10 分标杆**。
5. **i18n / 权限 / 测试** 三个横向能力**全员缺失**——122 页中 0 个页面有单元测试 / 0 个页面有 RBAC 粒度控制 / 0 个页面有 i18n 抽离。

## 1. 评分标准（0–10）

| 分段 | 含义 | 典型特征 |
|------|------|----------|
| 0 | 路由壳 / 跳转占位 | 文件 < 30 行，无功能 |
| 1 | 静态展示，无任何交互 | 仅 div + text，无状态、无事件 |
| 2 | 单屏 mock 看板 | 1–2 个 useState，仅展示 |
| 3 | 简单搜索/过滤 | 输入框 + 列表过滤 |
| 4 | 基础列表+分页+搜索 | 列表/卡片/分页/排序/筛选 |

| 6 | 状态机/审批流 | 多步表单 / 角色切换 / 状态变更 |
| 7 | 多 Tab + 复杂表单 + 联动 | Tab 切换 + 表单/详情/统计 联动 |
| 8 | 多维分析 + 图表 + 导出 | recharts/手写 SVG + 多种导出格式 + 联动筛选 |

## 4. 横向共性问题（Top 6 必修）

### 4.1 `// @ts-nocheck` 滥用

- **占比**：约 60/122 = 49%
- **风险**：类型系统失效，AI 辅助与代码评审失效，编译期错误被吞
- **建议**：v3.0.5.1 启用严格模式（`strictNullChecks`、`noImplicitAny`），逐文件移除 `// @ts-nocheck`，优先处理被引用的服务层（`services/api`）

### 4.2 7 个超大文件未拆分（TODO v3.0.4 逾期）

| 文件 | 行 | 状态 |
|------|----|----|
| CriticalValuePage.tsx | 4434 | P0 |
| PatientPage.tsx | 3624 | P0 |
| RegionalReportPage.tsx | 3347 | P0 |
| WorklistPage.tsx | 3266 | P0 |
| CostAnalysisPage.tsx | 2962 | P0 |
| OperationLogPage.tsx | 2804 | P0 |
| DevicePage.tsx | 2827 | P0 |
| PrintManagementPage.tsx | 2749 | P1 |
| PatientPortalPage.tsx | 2069 | P1 |

> 建议在 v3.0.5.1 中**先做拆分，不增加新功能**——P0 拆完预计 30 人日。

### 4.3 反模式代码

- `replayDeviceEvent('idle', { type: 'START_MAINTENANCE', notes: '...', by: 'system' }) as 'maintenance'`
  - 出现于 `DeviceOpsPage.tsx` / `TechMobileWorkstation.tsx` / `NuclearStatsPage.tsx`
  - **问题**：依赖运行时副作用做类型转换，是 XState/Machinery 滥用
  - **建议**：改为纯函数 `getStatus(event, current)`，状态机要可声明式

### 4.4 Mock 数据硬编码

- 多数页面在文件顶部 `const MOCK_xxx = [...]` 直接写死 50–200 条数据
- 任何筛选/翻页都不触发真实 API
- **建议**：建立 `useMockedApiAdapter()` 适配器，开发环境走 mock，生产环境走真实 fetch/axios；统一通过 `services/api/*` 暴露

### 4.5 i18n 缺口

- 122 个页面**0 个**调用 `useTranslation()` / `t()`
- 所有中文 UI 字符串硬编码
- **建议**：v3.0.5.1 引入 `react-i18next`，先抽取 20 个核心页面的高频字符串（~200 词条），后续迭代

### 4.6 测试覆盖率为 0

- 全项目未发现 `*.test.tsx` / `*.spec.tsx`
- **建议**：v3.0.5.1 起对 Bottom 50 的 P0/P1 页面强制编写 1 个 smoke test

## 7. 附录：审计方法与可重复性

### 7.1 评分模型

```
score = (
  functional_complexity  * 0.40  // 表单/CRUD/状态机
  + interactivity         * 0.20  // 用户可操作元素数
  + data_realism          * 0.15  // mock vs API
  + reusability           * 0.10  // 拆分度、组件复用
  + engineering           * 0.15  // 无 @ts-nocheck、无 TODO、有 i18n/测试
) * 10
```
